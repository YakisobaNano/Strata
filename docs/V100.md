# Tesla V100 (Volta, sm_70)

This port is based on upstream **v0.1.27**. V100 uses the pre-sm80 QSA paths already shipped for Turing:
FP32 native indexer scores, warp-based selection, and portable batched attention. TF32 MMA and cp.async
remain guarded and are never dispatched on Volta. Verify-window batching, fused generic kernels, the
batched MTP prompt pass, and both PLE I/O modes retain their upstream implementation.

## Build

Use an existing **CUDA 12.x** toolkit. CUDA 13 cannot compile Volta; the driver-reported CUDA compatibility
is not the installed compiler version. This machine was tested with CUDA **12.8.93**, GCC 13.3 and AVX2.
Do not change the driver, a toolkit, or a system CUDA symlink for this build.

```sh
cmake -S . -B build-v100 -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DSTRATA_ENABLE_CUDA=ON \
  -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc \
  -DCUDAToolkit_ROOT=/usr/local/cuda-12.8 \
  -DCMAKE_CUDA_ARCHITECTURES=70 \
  -DSTRATA_GGML_DIR="$PWD/third_party/llama.cpp" \
  -DSTRATA_V100_PARITY=ON -DSTRATA_PARITY_PROMPT_ATTN=ON
cmake --build build-v100 -j 12
```

The pinned llama.cpp source must already be available at `STRATA_GGML_DIR`. For setup-based builds,
`CUDA_PATH=/usr/local/cuda-12.8` selects this toolkit. Setup accepts capability 7.0+, excludes CUDA 13 for
Volta, and can select an already installed compatible GCC. No `STRATA_EXPERIMENTAL_SM75` flag is needed:
that option no longer exists in v0.1.27.

## BF16 and correctness

V100 has no native BF16 tensor cores. The CUDA 12.8 `cublasGemmEx` BF16-input/FP32-output API nevertheless
works on the tested V100; the production path keeps it. If cuBLAS rejects the operation with
`NOT_SUPPORTED` or `ARCH_MISMATCH`, the port expands BF16 bits exactly to FP32 and uses tiled SGEMM in
existing scratch memory. `STRATA_FORCE_BF16_FP32_GEMM=1` exercises that fallback on pre-sm80 devices.
HIP behavior and the FP16 quantized projection path are retained.

Before any GPU tests or model load, inspect `nvidia-smi` and ensure competing workloads have stopped.

```sh
ctest --test-dir build-v100 --output-on-failure
build-v100/qsa_prompt_attn_parity 4096 8 1
```

Standalone score parity includes CPU/FP64 score and top-k checks; BF16 parity exercises beta, output
stride/padding, small scratch tiling, a representative dense projection, and production dispatch.
The upstream `ple_parity` test requires independent ggml captures `bench/micro/ple_in.bin` and
`ple_out.bin`, the original table, and the matching dense pack. Missing fixtures remain failures.
The real-table `ple_reader_test --gguf <shard2> --rows 500 --direct-first` independently checks that
mmap/direct reads agree byte-for-byte. Attention tests execute and numerically validate the portable
fallback on pre-sm80 rather than treating refusal of an Ampere-only kernel as success by itself.

## Runtime and comparison

Use the **new `data/draft_vocab.bin`** in a private MTP runtime directory; link or reference existing
MTP weights there without modifying the old runtime. This retains the CJK draft head and its added
VRAM cost. Keep MTP, resident experts, and the saved PLE mode enabled in comparisons.

On Linux, upstream v0.1.27 counts physical cores; the old V100 build counted logical CPUs. For the saved
32-logical-CPU baseline, the port's benchmark specifies `--pool-workers 31` and grants every thread
CPUs 0–31, matching 31 workers plus the host. It also uses `--pcie-frac 0.55`, the old effective default,
in place of the new PCIe bandwidth probe's automatic value. These are benchmark settings, not source
changes. Context 4096, `--expert-cache 10721` (11252 actual slots), `--spec 4`, `--spec-min-p 0.5`,
`--prefill 2048`, PLE direct, temperature 0, seed 1, and max 512 output tokens are preserved.

Machine-specific raw logs and the final report are in `v100-results/` in the tested checkout.
